# R9-G-2 NONUTF8-ENV: `Environment.all()` leaves out a non-UTF-8 variable instead of panicking (2026-11-20) Plan

> Defect-queue entry R9-G-2 NONUTF8-ENV (P1 ratified 2026-11-17; SLICE-STATE § DEFECT QUEUE), quick win #3
> (`var/claude/aggregate-findings/2026-11-16/report.md`). Reproduced on the release binary at `6798829d`:
> `env $'BADVAR=\xff\xfe' phg run examples/process/args-env.phg` panics in `std::env::vars()` (exit 101), on every
> leg. Root cause [Verified: read the code]: `env_all` (`src/native/process.rs`) collects `std::env::vars()`, which
> panics on a non-Unicode key or value; `env_get` uses `std::env::var`, which returns an error there, so `get`
> already answers `null` for such a variable.

## Decisions Log
- [2026-11-20 13:28] ASSUMED (review): Environment.all() leaves out a pair whose key or value is not UTF-8, so it agrees with Environment.get (already null there) on every key; no new behaviour. Reading such a value lossily, or a bytes API, is DEC-590 (PENDING, recorded before this row started). Basis: advisor() 6C round 1 of R9-G-1 named this as the no-ruling route.

## Formal Plan

1. **Failing test first** (`tests/cli_argv.rs`, spawned on the three native legs with a cleared environment holding
   one good variable, one bad value and one bad key): exit 0, `all()` holds only the good one, `get` of the bad one
   is `null`.
2. **Fix**: `env_all` reads `std::env::vars_os()` and keeps a pair only when both halves are UTF-8.
3. **Sabotage, probe, SSOT, gate**: a mutant for the panicking reader, a lossy key and a lossy value; release binary
   probed on three legs; CHANGELOG, queue row out; full gate.
