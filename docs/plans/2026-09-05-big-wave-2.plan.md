- **Q-W2-3 (Lane R, 12 scout files)** — PHP `array{listing: RawListing, verdict: Verdict}` SHAPES
  have no phorj type; the lifter refuses them by name. Ruling wanted: should the lifter synthesize a

- **Q-W2-4 (Lane R, 3 scout files; LANGUAGE)** — phorj enums carry NO methods (`EnumDecl` has

  are common. Ruling wanted: methods on enums (a language feature — Invariant 16 cross-language
  scan: Rust/Kotlin/Swift/TS all allow them), or a lifter rewrite to a static helper class?
- **Q-W2-6 (checker, surfaced by the scout project check)** — an `if`-EXPRESSION with a `null`
  branch and a `T` branch is refused (`E-IF-BRANCH`: "branches must share one type") even where the
  context is `T?`; PHP's `$x ? null : $y` lifts to exactly that shape. Ruling wanted: unify
  `null`/`T` branches to `T?` (Kotlin/Swift/TS all do), or require an explicit `as T?` on one branch?
- **Q-W2-5 (Lane R, 3 scout files; LANGUAGE)** — `<=>` (spaceship) has no phorj operator; scout
